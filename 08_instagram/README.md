# Instagram-конвейер @relictum

Собирает готовые к постингу файлы из данных каталога и уже снятых ассетов.
Моделей не зовёт — работает при нулевом балансе Higgsfield.

## Команды

    node 08_instagram/build_feed.js --check          проверка ленты, ничего не пишет
    node 08_instagram/build_feed.js --id p03         собрать один пост
    node 08_instagram/build_feed.js --all            собрать все посты со статусом ready
    node --test 08_instagram/test/*.test.js          прогнать тесты

`node --test 08_instagram/test/` (с каталогом, без глоба) в этой версии Node
(проверено на v25.8.1) падает с `Cannot find module` — раннер не обходит
каталог сам. Рабочая форма — глоб по файлам теста, как выше.

Результат — `08_instagram/out/<дата>_<рубрика>_<экспонат>/`: кадры `01…NN`
в порядке листания, `caption.txt`, `meta.json`. Папка в `.gitignore`.

## Что где

| Файл | Роль |
|---|---|
| `feed-data.js` | единственный источник правды по ленте, правится руками |
| `eras-data.js` | справочник геологических подразделений (эон/эра/период/эпоха) по Международной хроностратиграфической шкале (ICS) — третий источник фактов, для датировок на карточках рубрики `era` |
| `lib/sources.js` | загрузка `shared/catalog.js`, `16_product_promos/promo-data.js` и `eras-data.js` |
| `lib/facts.js` | сверка фактов поста с этими тремя источниками + привязка факта к экспонату поста |
| `lib/feed-schema.js` | валидация постов, пределов карточек, ритма 2+1 и раскладки сетки |
| `lib/render-card.js` | HTML-шаблон → PNG через headless Chrome |
| `lib/render-video.js` | mp4/jpg → центральный кроп 4:5 или 1:1 через ffmpeg |
| `lib/paths.js` | общие пути (репо, `shared/img`, шаблоны, `out/`) |
| `templates/` | HTML-шаблоны карточек: `cover`, `figure`, `era`, `spec`, `end` + общий `card.css` |
| `board.js` | борд ленты на `index.html`: сетка, фильтр по рубрикам, таблица статусов |

## Источники фактов и их ключи

Три источника, и у каждого свой тип ключа — здесь легко ошибиться:

- `catalog.js:<slug>.<путь>` — паспорт экспоната из `shared/catalog.js`, ключ — **slug**.
- `promo-data.js:<id>.<путь>` — запись из `16_product_promos/promo-data.js`, ключ — **id** вида
  `R–0609` (тире длинное, не дефис).
- `eras.js:<slug>.<путь>` — геологическое подразделение из `eras-data.js`, ключ — **слаг
  подразделения** (`pleistocene`, `cretaceous`, `paleozoic`, `hadean`…).

## Правило «показано — значит сверено»

Каждое утверждение, которое зритель видит прямо на карточке, обязано дословно
совпадать с фактом поста (`post.facts[]`), а факт — резолвиться в один из трёх
источников выше. Проверяемое поле задаётся шаблоном карточки:

- `era` — датировка (`data.when`);
- `figure` — крупное число (`data.big`);
- `spec` — значение каждой строки паспорта (`data.rows[i][1]`).

Шаблоны `cover` и `end` проверяемых утверждений не несут (обложка и служебная
закрывающая карточка) и в эту проверку не входят.

Если у поста задан экспонат (`post.exhibit`), факты обязаны ссылаться именно
на него: для `catalog.js` ключ ссылки должен совпадать со slug'ом поста, для
`promo-data.js` — с полем `id` того же экспоната. Ссылка на паспорт соседнего
товара такую проверку не пройдёт. У `eras.js` привязки к экспонату нет —
эпоха не принадлежит конкретному товару.

## Пределы карточек

Проверяются на входе валидатором, не подгонкой шрифта на рендере — карточки
должны быть свёрстаны, а не сжаты до нечитаемого:

- паспорт (`spec`) — не больше 5 строк в `data.rows`;
- любое текстовое значение в данных карточки — не длиннее 220 знаков;
- заголовок карточки (`data.title` / `data.name`) — не длиннее 60 знаков.

## Раскладка «крестиком»

Лента Instagram читается сеткой по три плитки в ряд. Ритм 2+1 (в каждой
тройке слотов ровно один товарный пост) сам по себе не мешает всем товарным
постам оказаться в одной и той же колонке сетки — тогда при скролле видна
сплошная вертикальная полоса вместо чередования. `checkGridLayout` в
`lib/feed-schema.js` проверяет это отдельно: среди товарных постов должно
быть больше одной разной колонки.

## Кроп: только центральный

Подложки под кадр пробовали и отклонили: размытая копия фона даёт «призрак»
объекта по краям, заливка цветом — заметный шов (фон исходников
неоднороден). Остался только центральный кроп по высоте с масштабированием
под целевой формат (`lib/render-video.js`).

## Компромисс по апскейлу спинов

360°-видео (спины) сняты горизонтально, около 1284×716. При центральном
кропе по высоте это даёт заметный апскейл: ×1,9 в формате 4:5, ×1,5 в
формате 1:1. Поэтому спинам в ленте всегда ставится кроп `1:1`, а
`renderVideo`/`renderPhoto` предупреждают в stderr, когда коэффициент
масштабирования превышает порог (сейчас ×1,6).

## Правила

- Ноль npm-зависимостей: только Node, Chrome и ffmpeg.
- Шрифты — `shared/fonts.css`, Google Fonts запрещены.
- `frames[].src` — имя файла в `shared/img`, не путь и не URL.
- `catalog.js` адресуется по `slug`, `promo-data.js` — по `id` вида `R–0609` (длинное тире),
  `eras-data.js` — по слагу геологического подразделения.

## Добивка ассетов

Покрытие на 14.08.2026: 360°-видео (`spin`) — у 37 экспонатов из 79, интерьеры
(`interior`) — у 61, «встретить живым» (`alive`) — у 36. Генерация — через
скилл `.claude/skills/relictum-product-promo/`. Higgsfield доступен локально
через CLI `higgsfield`; MCP-коннектор не авторизован. Canvas в Higgsfield нет
(проверено 14.08.2026).

Экспонату `R–0228` (череп льва №2) новые ракурсы не генерировать — единственный
исходник фронтальный и низкого разрешения, модель уже дважды удлиняла морду
до медвежьей/гиеновой. Ждём боковой снимок от Михаила.
