# RELICTUM — конвейер контента для Instagram

Дата: 14.08.2026 · Статус: согласовано владельцем, готово к плану реализации

---

## 1. Задача

Собирать посты для @relictum из того, что уже снято для сайта: 360°-видео, интерьерные
проезды, анимированные эпохи, галереи экспонатов. Конвейер должен давать две вещи сразу:

1. **готовые к постингу файлы** — открыл папку, залил в Instagram;
2. **борд** — видно всю ленту сеткой, ритм, календарь и статус каждого поста.

Первая партия — месяц ленты, ~15 постов.

## 3. Архитектура

Четыре слоя, всё внутри `08_instagram/`. Паттерн повторяет уже работающий конвейер
печатного каталога (`catalog_data.js` → `render_catalog_pdf.js` → PDF).

```
08_instagram/
  feed-data.js          ← единственный источник правды по ленте
  templates/*.html      ← шаблоны карточек на токенах сайта
  build_feed.js         ← сборщик: HTML→PNG, ffmpeg-нарезка
  index.html            ← борд (расширяем существующий макет)
  out/                  ← результат, в git не кладём
```

### 3.1 Данные — `feed-data.js`

Один массив постов. Всё остальное — производное; руками правится только этот файл.

```js
window.RELICTUM_FEED = [
  {
    id: "p01",
    date: "2026-08-18",
    rubric: "object",              // object | figure | interior | expedition | ritual | editions
    slot: 1,                       // позиция в сетке, задаёт ритм 2+1
    exhibit: "megalodon-tooth",    // slug из catalog.js; null для «воздушных» постов
    format: "carousel",            // carousel | reel | single
    frames: [
      { type: "video", src: "spin_megalodon.mp4", crop: "4:5", trim: [0, 5] },
      { type: "card",  tpl: "figure", data: { big: "≈ 23 млн лет", sub: "миоцен" } },
      { type: "photo", src: "int_ph_megalodon.jpg", crop: "4:5" },
      { type: "card",  tpl: "end" }
    ],
    caption: { lead: "", body: "", cta: "" },
    tags: [],
    facts: [
      { claim: "возраст", value: "≈ 23 млн лет, миоцен",
        source: "catalog.js:megalodon-tooth.age", checked: true }
    ],
    status: "draft",               // draft | ready | blocked
    blockers: []
  }
]
```

Правило: `frames[].src` — только имя файла в `shared/img`. Никаких внешних URL.

### 3.2 Шаблоны карточек — `templates/*.html`

Вёрстка на дизайн-токенах сайта: ivory `#F4F0E8`, bone `#FBF8F1`, black `#111111`,
bronze `#B08A55`, deep `#9A6D34`; Cormorant Garamond для заголовков, Inter для служебного.
Шрифты подключаются `@font-face` с локальных woff2.

| Шаблон | Роль |
|---|---|
| `cover` | обложка карусели: кадр + кикер + заголовок |
| `figure` | рубрика «Цифра»: возраст/размер крупной типографикой |
| `era` | карточка эпохи: кадр + «66 млн лет назад» + факт |
| `spec` | паспорт экспоната: период, регион, размер, оформление |
| `end` | финальная: логотип + «по запросу в галерею» |

Шаблон принимает JSON из `frames[].data` через query-параметр или временный JSON-файл;
всё остальное — статическая вёрстка.

### 3.3 Сборщик — `build_feed.js` (node)

Гибрид: **типографика — вёрсткой, картинка и движение — из готового, модели — только там,
где ассета нет.**

- **Карточки:** шаблон → Chrome headless → PNG 1080×1350.
  `--headless --screenshot --window-size=1080,1350 --hide-scrollbars --force-device-scale-factor=1`
- **Видео:** ffmpeg-кроп готовых mp4. Спины сняты 9:16 → в 4:5 центральным кропом:
  `-vf "crop=iw:iw*5/4,scale=1080:1350:flags=lanczos" -c:v libx264 -crf 20 -pix_fmt yuv420p`
  Для 1:1 — `crop=iw:iw`. Reels требуют аудиодорожку — добавляем тишину через `anullsrc`.
- **Обложки видео:** `ffmpeg -ss 2.5 -i <video> -frames:v 1 -q:v 2` (домашний рецепт из `CLAUDE.md`).
- **Ничего уже снятого не перегенерируем.**

Вывод — папка на пост, файлы в порядке листания:

```
out/2026-08-18_object_megalodon/
  01.png  02.mp4  03.png  04.png
  caption.txt
  meta.json
```

CLI:

```
node 08_instagram/build_feed.js --check     # только проверка готовности, ничего не пишет
node 08_instagram/build_feed.js --id p01    # собрать один пост
node 08_instagram/build_feed.js --all       # собрать всё, что status=ready
```

### 3.4 Борд — `index.html`

Расширяем существующий макет. Читает `feed-data.js` и показывает:

- сетку 3-в-ряд в реальном порядке публикации — виден ритм «крестиком»;
- превью каждого поста как в Instagram (уже есть в макете);
- календарь по датам;
- фильтр по рубрикам;
- **статус каждого поста**: готов / нет ассета / факт не проверен, с указанием чего именно нет.

Статика, без бэкенда. Живёт на GitHub Pages вместе с сайтом.

## 4. Ритм и рубрики

Ритм **2+1**: в каждой тройке два «воздушных» поста и один товарный. При скролле читается
крестиком. Поле `slot` в `feed-data.js` задаёт позицию, борд проверяет, что ритм не сбит.

Рубрики — из `08_instagram/index.html`, без изменений:

| Рубрика | Что это | Частота |
|---|---|---|
| Объект недели | Один предмет, одна история, макросъёмка | 1 × нед |
| Цифра | Типографическая карточка: возраст, размер, тираж | 1 × нед |
| Интерьер | Объект в пространстве: ниша, библиотека, атриум | 2 × мес |
| Экспедиции | Дневники раскопок, «до/после» препарации | 2 × мес |
| Ритуал | Упаковка, перчатки, сургуч | 1 × мес |
| Editions | Анонсы тиражей. Единственная рубрика, где допустима срочность | по релизам |

Карусели-эпохи (из `public/eras/era-*.html`) идут внутри рубрики «Цифра» как её видовой
подтип — отдельной рубрики не заводим.

## 5. Достоверность фактов

Отдельная стадия **до** вёрстки.

- Каждое число в посте живёт в `facts[]` с полем `source`, указывающим на конкретное поле
  паспорта: `catalog.js:<slug>.age`, `promo-data.js:<slug>.era.text` и т. п.
- `--check` проверяет, что поле по этому пути реально существует и значение совпадает.
- **Не проверено — не публикуется.** Пост без источника у факта получает `status: "blocked"`.
- Факты берутся из паспортов, а не сочиняются моделью. Спорные выносятся владельцу списком.

**Персональный запрет:** череп пещерного льва № 2 (`R–0228`) — по `CLAUDE.md` новые ракурсы
ему не генерировать до бокового снимка в hi-res от Михаила и подтверждения атрибуции.
В ленту идёт только пиксельно-верными кропами исходника.

## 6. Тексты

По правилам дома:

- люксовый регистр, короткие фразы; без шуток, сленга, капса и восклицаний;
- формула подписи — одно из трёх: интересный факт / в чём особенность / для какого интерьера;
- без буллет-пойнтов и списков;
- не дублировать то, что видно на самой карточке;
- цена — «по запросу в галерею», конкретные суммы в подписях не публикуем;
- **тема подлинности на витрине не поднимается**;
- имена и термины — полностью, без сокращений.

Процесс: субагент получает эталонные описания с сайта, факты по экспонату и список слотов
с лимитами; отдаёт строгий JSON «слот → текст»; скрипт подставляет в `feed-data.js`.
Главный агент только проверяет и правит точечно.

## 7. Higgsfield — добивка, не основа

Модели зовём только там, где ассета нет. Рецепты уже канонизированы в `CLAUDE.md`:

- **музейное видео (чёрная студия):** `nano_banana` кадр «pure black studio, white museum
  spotlight, rim light» → `kling3_0_turbo` image-to-video;
- **интерьер:** `nano_banana_pro`, реф = наше студийное фото или `job_id` прошлой генерации;
- **360°:** `kling3_0_turbo`, start_image = студийное фото, duration 5.
  Пресет «IN THE DARK» ретраить с `declined_preset_id`.

Выполняется **в облачной сессии** — локально Higgsfield недоступен.

**Canvas:** проверить в облачной сессии, есть ли он среди инструментов Higgsfield MCP.
Если есть — подключаем как дополнительный источник кадров. Если нет — конвейер не страдает,
борд у нас свой. Конвейер не должен зависеть от наличия Canvas.

- перегенерацию уже снятых ассетов.

## 10. Критерии готовности

Первая партия считается сделанной, когда:

1. `feed-data.js` содержит 15 постов на месяц, ритм 2+1 не нарушен;
2. `build_feed.js --check` проходит без единого `blocked`: у каждого факта есть живой источник;
3. `build_feed.js --all` собирает 15 папок с файлами в порядке листания и `caption.txt`;
4. борд открывается и показывает сетку, календарь и статусы;
5. все тексты прошли правила дома (регистр, формула подписи, без темы подлинности);
6. ни один PNG не содержит Google-шрифтов — только локальные woff2.
